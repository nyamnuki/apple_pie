이 5장은 서로 **그리는 난이도가 다른 다섯 종류**라서, 이것만 통과하면 나머지 38장은 같은 방식으로 찍어낼 수 있습니다.

**시범 5장 합격 기준** (5장을 넣은 뒤 확인)

1. 5장을 나란히 놓았을 때 **크기가 고르게 보인다** (하나가 더 크거나 작아 보이지 않는다)
2. 바닥 그림자의 **높이와 진하기가 같다** (나란히 센 줄이 울퉁불퉁해 보이지 않는다)
3. 남은 38장의 코드 SVG 와 **같은 종이 위 그림처럼** 섞인다 (한 장만 튀지 않는다)
4. `npm run test:unit` 의 `그림 현황` 이 `mathItem: 3/30`, `resource: 2/13` 로 나온다
5. `npm run build` 가 `그림 5장, 0.1?MB` 로 찍힌다

### 3-2. 그래서 넣는 크기

| 항목 | 값 | 이유 |
|---|---|---|
| **넣는 파일** | **256 × 256** | 64px(`#gallery`)의 4배, 56px(도감)의 4.5배, 136px(크게 보기)의 1.9배 |
| 보관용 원본 | 512 × 512 | 나중에 더 크게 쓸 일이 생기면 다시 뽑습니다. **저장소에는 넣지 않습니다** |
| 파일 형식 | WebP (품질 80~85) | 같은 그림이 PNG 의 1/3~1/4 용량 |
| 한 장 목표 용량 | **25KB 이하** | 43장 × 25KB = 약 1.1MB |
| 43장 합계 상한 | **1.2MB** | 전체 예산 6MB 중 이만큼만 씁니다 (나머지 66장이 4.8MB 를 씁니다) |

> **136px 짜리 '스티커 크게 보기'만 1.9배 확대입니다.** 수채화는 번지는 그림이라 이 정도 확대는 눈에 띄지 않습니다.
> 넣어 보고 흐려 보이면 **그 때** 43장을 384×384 로 다시 뽑습니다 (용량 +0.9MB, 예산 안에 들어갑니다).
> 처음부터 384 로 가지 않는 이유는, 뒤 단계의 배경·가구가 예산의 큰 몫을 쓰기 때문입니다.
>
> 22px 처럼 아주 작게 보일 때는 256px 그림이 11분의 1 로 줄어듭니다.
> 그래서 **가는 선과 작은 점무늬는 아래 4-4 의 최소 굵기**를 지켜야 뭉개지지 않습니다.

## 4. 이미지 규격

### 4-1. 좌표 — 지금 코드 그림을 그대로 옮기는 표

현재 모든 물건은 **64 × 64 칸** 안에 그려져 있습니다 (`src/components/art/itemArt.tsx` 의 `viewBox="0 0 64 64"`).
**256px 파일에서는 전부 4배**입니다.

| 기준 | 64칸 좌표 | **256px 좌표** |
|---|---|---|
| 그림판 전체 | 0~64 | 0~256 |
| 물체 가운데 | (32, 34) | **(128, 136)** |
| 물체가 들어가는 범위 | x 4~60, y 4~58 | **x 16~240, y 16~232** |
| 사방 여백 (건드리지 않음) | 4칸 이상 | **16px 이상** |
| 바닥 그림자 가운데 | (32, 58) | **(128, 232)** |
| 바닥 그림자 가로 반지름 | 10~20 | **40~80** |
| 바닥 그림자 세로 반지름 | 3.5 | **14** |

### 4-2. 반드시 지킬 것

1. **정사각형** — 1:1 이 아니면 `object-contain` 때문에 위아래(또는 좌우)에 빈 띠가 생기고, 물건이 혼자 작아 보입니다.
2. **투명 배경** — 종이색·흰색을 바닥에 깔지 마세요. 크림색 카드 위, 색 있는 칩 위, 어두워진 밤 방 등 여러 바탕에 올라갑니다.
3. **여백을 43장 모두 똑같이** — 아이가 **개수를 세는** 화면입니다. 한 장만 여백이 좁으면 그 물건이 더 커 보이고, 센 줄이 울퉁불퉁해집니다. 가장 중요한 규칙입니다.
4. **바닥 그림자를 그림 안에 그려 넣습니다** — 앱은 그림자를 따로 넣지 않습니다. 위 표의 타원 위치·크기로, `#59483C` 불투명도 **14%**, 테두리 없이 번지게. 날아다니는 것(구름·연)은 4-5 참고.
5. **수채화 질감을 그림에 구워 넣습니다** — 코드 SVG 는 `#wc-small` 필터로 번짐을 입지만, **PNG·WebP 에는 필터가 걸리지 않습니다** (`src/components/AssetIcon.tsx` 는 그냥 `<img>` 입니다). 가장자리 흔들림, 물감이 고인 진한 테두리, 옅은 알갱이를 **그릴 때 넣어야** 나머지 코드 SVG 와 섞입니다.
6. **그림 안에 글자·숫자를 넣지 않습니다** — 한국어·영어 두 언어를 쓰고, 숫자는 게임이 따로 붙입니다.
7. **오른쪽 위 꼭대기를 비워 둡니다** — 게임이 센 순서 숫자(`ItemToken` 의 배지)와 드문 재료 반짝이를 그 자리에 올립니다. 256px 기준 **오른쪽 위 48×48 안에는 중요한 것을 두지 마세요.**

### 4-3. 빛과 그림자 (43장 전부 같게)

- 빛은 **왼쪽 위**에서 옵니다. 예외 없습니다.
- 둥근 것: 왼쪽 위에 **흰색 반투명 물감 자국 하나** (현재 코드의 `Shine`: 가로 20px, 세로 12px 정도의 비스듬한 타원, 흰색 50%).
- 오른쪽 아래 가장자리에 옅은 그늘 한 겹.
- **딱딱한 그림자, 검은 그림자, 여러 방향 빛은 쓰지 않습니다.**

### 4-4. 선과 최소 굵기

| 항목 | 값 |
|---|---|
| 테두리 색 | `#6B5444` (갈색 색연필). **검정 금지** |


개발 중이면 개발 서버(`npm run dev`)를 **끄고 다시 켭니다.** 새로고침만으로는 새 그림이 보이지 않습니다.
